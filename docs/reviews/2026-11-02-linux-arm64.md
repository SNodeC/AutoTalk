## Architectural change

Invariant: native tools must match both the OS and CPU architecture, with one
platform authority for runtime setup and package eligibility. Previously the
runtime and builder separately allowed one CPU architecture per OS.

The existing binary manifest is now keyed by OS and normalized machine name.
Its redundant architecture field was removed. The native builder calls the same
platform check, deleting its parallel allowlist. Linux aarch64 selects official
ARM64 uv and Codex archives, using pinned SHA-256 digests:

- uv 0.12.19, `aarch64-unknown-linux-gnu`:
  `0804e9b164c64b6914182d5920c08551958a095986f10a3731056df701126436`
- Codex 0.157.0, `aarch64-unknown-linux-musl`:
  `e6fbe2798e941b833f7e3bc34010f7443240ac4a149ce1876f32cbfa0ba7d25f`

The Linux vLLM-Omni backend, speech deployment configuration, model lifecycle,
application interface, project format, and dependency pins are shared unchanged.
The existing builder names the ARM64 package `AutoTalk-0.1.0-linux-aarch64.tar.gz`
and emits its checksum. No second backend or alternate installation flow was added.

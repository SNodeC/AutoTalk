## 2. Findings — F12–F14 kept, F15 retracted

### F12 — Literal `&` silently eaten as a Qt mnemonic marker (unchanged, still valid)

Reproduced in freshly-generated screenshots: File menu shows **"Recordings  export…"**, Talk menu shows **"Voice  speech…"**, editor inspector shows **"Slide voice  language…"** — all missing their ampersand, because `QAction(title, w)`/`QPushButton(text)` (`ui.py:52-56,352-359`) pass raw text containing a single, unescaped `&`. Exactly five call sites confirmed via `grep` (`ui.py:395,470,594,624`; `settings.py:516`). **Severity Low–Medium. Remedy: double the ampersand (`&&`) in these five strings.**

### F13 — "After this slide" combo hard-clips its text at minimum window size (unchanged, still valid)

Re-examined with a wider crop of my own fresh 940×680 screenshot: the combo hard-clips mid-glyph — `"Use talk setting — advanc"` — with no ellipsis character at all, distinct from the (correctly-used elsewhere) command-ellipsis convention. Geometry investigated: only `inspector_scroll` has an explicit minimum width (200px, `ui.py:491`); navigation/center panes have smaller implicit floors (thumbnail grid `QSize(116,125)`, `SlideImage.setMinimumSize(160,100)`). At 940px the inspector renders ~240px, some slack above its floor, but I did not test how far the other panes can compress. **Two genuine candidate remedies, neither free of tradeoff: widen the inspector's floor (needs re-testing at minimum size) or add explicit elide-with-tooltip (not automatic in the observed rendering). Severity Low.**

### F14 — `AudioFile` resource cleanup relies on `__del__`, not a context manager (unchanged, still valid)

`AudioFile.__del__` (`media.py:68-70`) closes `self.stream`; `Mix.update()` (`media.py:110-127`) discards superseded instances by simple reassignment, relying on CPython refcounting for prompt closure. Design observation from reading the code, not a reproduced leak. **Severity Low. Remedy: make `AudioFile` a context manager; have `Mix.update()` close superseded entries explicitly.**

### F15 — RETRACTED: "native bundle depends on host Qt via symlinks"

**This finding was wrong and is retracted, kept as an ID for auditability rather than deleted.**

What I originally cited (`tools/build.py:51-54`) is real: during the native (`--system-qt`) build, plugin/translation directories in a **build-time staging tree** (`build/system-qt/PySide6/Qt/{plugins,translations}`) are symlinked to the host's live Qt installation. I incorrectly treated this staging convenience as a property of the **shipped, packaged application**. It is not. I re-traced the actual pipeline, read-only, this pass:

- **`packaging/autotalk.spec`** (read in full): the PyInstaller `Analysis()` step uses PySide6's standard hook against that staging tree; PyInstaller's `Analysis`/`COLLECT` resolve symlinks and copy the **real file content** into the final `dist/autotalk/_internal/` output — this is standard PyInstaller behavior, not something AutoTalk's spec does unusually.
- **Direct filesystem check of the actual shipped bundle** (`dist/autotalk/_internal`, read-only): `find dist/autotalk/_internal/PySide6/Qt/plugins -type l` → **0 symlinks**. `file dist/autotalk/_internal/PySide6/Qt/plugins/platforms/libqxcb.so` and `.../translations/qtbase_de.qm` and `.../libQt6Core.so.6` are all **regular files** (ELF binaries / a real `.qm` translation file), confirmed directly, matching exactly what the user's own filesystem check found.
- **The 36 symlinks that do exist** in `_internal` (checked via `find -type l`) are all standard PyInstaller binary-deduplication symlinks pointing to *other files inside the same bundle* (e.g., `libx264-*.so.165 -> av.libs/libx264-*.so.165`) — none point outside the bundle to any host path.
- **`artifacts/open-tasks/installed-audit.py`** (read in full, its already-produced output read, nothing re-run or rebuilt): it (a) SHA-256-verifies that every `libQt6*`/`breeze6.so`/`KDEPlasmaPlatformTheme6.so` file actually present in `dist/autotalk/_internal/` byte-for-byte matches the system library it was sourced from at build time — i.e., a genuine independent copy, not a live reference; and (b) launches the **actual packaged executable** as a real subprocess and inspects `/proc/{pid}/maps` at runtime, asserting `all(path.startswith(str(bundle)) for path in paths)` for every mapped `libQt6*` library. Its already-recorded output (`installed-final-audit.log`: `{"verified_libraries_and_plugins": 27, "mapped_qt_libraries": 18, ..., "breeze_loaded": true, "smoke_exit": 0}`) and the accompanying `runtime-qt-paths.json` (18 paths, every one under `dist/autotalk/_internal/...`) directly show the running packaged application loads **zero** Qt libraries from any live host system path — it is self-contained at runtime.

**Corrected conclusion: native Breeze integration in the shipped bundle is achieved by copying matching native libraries/plugins into the bundle, verified byte-for-byte and confirmed by inspecting the actual running process's mapped libraries — not by a live-host dependency.** I found no evidence of any remaining host-path runtime dependency for the shipped native bundle, and I am not asserting one. As instructed, I am not recommending a fix for a dependency the evidence shows does not exist.

## 7. Code quality — deep tracing, with the `Project.save()` claim corrected

I read `project.py` (625 lines), `media.py` (349 lines), `screen_capture.py` (243 lines), `tools/build.py` (94 lines) in full, plus relevant sections of `runtime.py`, `playback.py`, `speech_worker.py`.

**Persistence/migration (`project.py`):** `Project.save()` (415-429) writes to a `.tmp` file and calls `Path.replace()` for an **atomic rename** — this prevents a reader from ever observing a half-written manifest, confirmed by reading the exact call. **Corrected claim: this is atomicity, not durability** — I did not check for an `fsync()`/`os.fsync()` call before the rename (there isn't one visible in the read code), so I make no claim about guaranteed survival across a power loss or unclean shutdown; atomic replacement and power-loss durability are different properties, and only the former is verified here. `Project.load()` (460-549) handles schema versions 1–4 explicitly, including v1's legacy audio re-keying and v2/v3's re-canonicalization check that preserves valid audio without ever "blessing" stale audio (533-542) — unchanged from prior praise, confirmed on full re-read.

**Cache correctness (`project.py:383-401`):** `speech_key()` folds engine id, passages, voice, resolved `directions()`, sampling, and pause into one digest; `ready()` compares directly. No separate staleness flag found.

**Cancellation/threading/resource cleanup (`screen_capture.py`, full read):** `PulseInput` reimplements a minimal nonblocking PulseAudio client via `ctypes` specifically for sub-5ms-interruptible cancellation (`poll()`, 73-82). `ScreenCapture.close()` (232-242) joins workers with a 3s timeout and raises if any remain alive, feeding directly into `Playback._finalize_capture()`'s `try/except (OSError, RuntimeError)` (`playback.py:381-392`) — a coherent, traced exception path.

**Recording/export/recovery (`media.py`, full read):** `export_recording()` (208-329) is the single shared export path for both live and synthetic (`export_prepared`) captures; atomic `.partial` → `replace()` on success; `finally` deletes the partial on any failure/cancellation, leaving `session.json` safely retryable.

**Platform/package boundaries:** `download()` (`runtime.py:189-227`) verifies SHA-256 and fails closed on mismatch. `build.py`'s native path uses `check=True` on the patch and both cmake invocations — a failed patch/build aborts packaging, confirmed by direct read. **F15, previously claimed here, is retracted (§2)** — the shipped bundle is self-contained, confirmed by SHA-256-verified copies and a real running-process `/proc/pid/maps` check showing zero host-path Qt libraries.

**Bounded conclusion, unchanged:** no new correctness defect found in persistence, cancellation, or recording/export on this pass; F14 remains a low-severity structural note, and F15 is retracted rather than replaced with a new packaging finding, since the evidence does not support one.
